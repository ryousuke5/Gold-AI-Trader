# GOLD H4_H1PR_01 仮想フォワード監視EA

## 目的

凍結済み `H4_H1PR_01` の条件を、XMデモ口座のGOLD#チャートで**発注せず**に監視し、仮想エントリー・仮想決済を記録する研究用EAです。手動プローブEAとは別物です。

- `OrderSend` / `OrderClose` / `OrderModify` などの発注APIを含みません。
- H4 EMA200の初期値依存を抑えるため、初期値はM5履歴60,000本・完全なUTC H4足1,000本以上を要求します。MT4側に必要な履歴が不足する場合は監視を開始せず、履歴が揃うまで待機します。
- 週末など `TimeCurrent()` が古く、現在のサーバーUTC+2/+3時差を確認できない状態でも初期化は可能です。ただし、時差確認が通る最初の新しいGOLD#ティックまで `MONITOR_BLOCKED` として監視・シグナル処理を停止します。
- デフォルトでデモ口座のみを許可し、チャート銘柄は `GOLD#` に固定します。
- MT4の完了済みM5 BID足からUTC基準のH1/H4を再構築します。H1/H4のサーバー足をそのまま使いません。
- 不完全なM5集合、DST切替の曖昧な時間帯、UTC足境界と一致しないエントリーは除外し、理由を記録します。
- 仮想ポジション状態と最終処理済みシグナル時刻はMT4端末のGlobal Variablesに保存し、再起動時の二重エントリーを防ぎます。
- 同じデモ口座・GOLD#では、このEAを1チャートだけに添付してください。複数インスタンスの同時実行はサポート対象外です。

## 凍結ルール

1. H4方向：最新の完了済みUTC H4足で、BUYは終値 > EMA50 > EMA200、SELLは終値 < EMA50 < EMA200。
2. H1シグナル：直前H1足の安値（BUY）/高値（SELL）が直前H1 EMA20から0.15×直前ATR14以内。シグナル足は直前高値/安値を抜け、EMA20を超え、足色・終値位置・RSI条件を満たす。
3. 次のUTC H1始値までのギャップがシグナルATR14の0.75倍以内。始値後30秒を超えた検出は遅延として除外。
4. BUYはAsk仮想エントリー、SELLはBid仮想エントリー。BUY決済判定はBid、SELL決済判定はAsk。
5. BUY SLは直前3本の完了済みH1安値の最小値−0.10×ATR。SELL SLは直前3本の完了済みH1高値の最大値＋エントリー時スプレッド＋0.10×ATR。
6. 初期リスクは0.60〜2.80 ATR、TPは2R、最大保有は24時間（24 H1本相当）。初期H4 EMA200の安定化のため、完了済みUTC H4足を最低260本要求します。
7. ストップを先に判定し、データギャップが3時間を超えた場合は再開後の最初の観測可能なBid/Askで `DATA_GAP_EXIT` として仮想決済。
8. 同時保有は1ポジションまで。追加の1時間クールダウンは入れず、バックテスト実装と同じく、決済後の次の適格シグナルを次のH1始値で評価します。

## 重要な時刻制約

MT4の履歴時刻からUTCへの変換は、XMサーバーが冬UTC+2／夏UTC+3でEU DSTカレンダー（3月最終日曜〜10月最終日曜）に従うことを仮定します。XMTradingの案内も冬GMT+2・夏GMT+3と欧州の夏時間期間を掲載しています。起動時と各Tickで、現在の `TimeCurrent()-TimeGMT()` がその時刻表に合うか照合し、合わない場合は監視をブロックします。3月の切替時03時台と、10月の重複する03時台は曖昧なため除外します。

この照合は**現在のオフセットしか実測確認できず、過去履歴の全期間についてXMのDST規則を証明するものではありません**。複数の固定時刻サンプルでMT4のM5バー時刻・GMT・UTC再構成が一致することを確認するまで、検証を「UTC完全一致」と認定しないでください。サーバーが別のDSTルールならEAは停止するか、履歴変換がずれる可能性があります。

## インストール

1. XMデモ口座のMT4のみを使います。
2. 「ファイル → データフォルダを開く → MQL4 → Experts」に `GOLD_H4_H1PR01_VirtualMonitor.mq4` を配置します。
3. MetaEditorでコンパイルします。コンパイルエラーがあればEAを起動せず、エラー全文を確認します。
4. `GOLD#` チャートに添付します。 `RequireDemoAccount=true` のままにします。週末に添付した場合は、最初の新しいGOLD#ティックで時差確認が通るまで `MONITOR_BLOCKED` になります。
5. Expertsログで「Virtual entries only」「No trading functions」の起動メッセージを確認します。
6. `MQL4/Files/GOLD_H4_H1PR01_ForwardEvents.csv` に `MONITOR_START`、`SIGNAL_CHECK`、`VIRTUAL_ENTRY`、`VIRTUAL_EXIT` 等が出力されます。 `quote_based_R_pre_fee` はBid/Askに基づく仮想Rで、スリッページ・手数料・スワップ控除前です。

このEAは仮想取引のみです。実際のBid/Askを使った価格追跡ですが、仮想約定であり、ブローカーの実約定・スリッページを再現するものではありません。実約定コストは別のデモ計測EAで計測します。次のH1始値後30秒以内に観測できなかったシグナルは `ENTRY_DELAY_EXCEEDED` として除外します。この30秒は戦略条件ではなく、次足始値の再現性を保つための事前固定した監視品質ルールです。

## 最初の受入確認

- MetaEditorのコンパイル成功（警告も保存）。
- `MONITOR_BLOCKED` の場合は、最初の新しいティックで `MONITOR_RESUMED` が出てから監視が始まること。
- 完全なUTC H4足が1,000本以上再構築されていること（初期設定）。
- Expertsログでデモ口座ガード・銘柄ガードが通過。
- イベントCSVに時刻・UTC/サーバー時差・Bid/Ask/Spreadが出力。
- 最初の起動時に過去シグナルを遡って仮想エントリーしない。
- コード内に発注APIが存在しないことを静的テストで確認。
- UTC H1/H4足が既知のM5時刻サンプルと一致。
- MQL4コンパイルとUTC時刻の照合が完了するまでは、成績データとして扱わない。

## 出力の共有

`GOLD_H4_H1PR01_ForwardEvents.csv` とMetaEditorのコンパイル結果を共有してください。口座番号、口座名、個人情報を含むログは事前に確認・削除してください。
